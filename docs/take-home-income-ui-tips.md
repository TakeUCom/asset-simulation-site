# 手取り計算ロジック UI/UX Tips

このメモは、手取り計算ロジックを画面で分かりやすく伝えるためのデザイン指針である。

## 1. まず伝えるべきこと

ユーザーが知りたいのは税務の細かい式そのものではなく、次の3点である。

- 今の年収だと、実際に使えるお金はいくらか
- その前提で、毎年どれくらい余剰が出るか
- どこまでが概算で、どこから先は個別条件で変わるのか

そのため、UIでは「詳細な税額」よりも「使えるお金」と「前提条件の透明性」を優先する。

## 2. 推奨表示構成

### 2.1 収入入力エリア

入力直後に、次の3つを並べて表示する。

- 世帯年収（額面）
- 世帯手取り（概算）
- 月額手取り（目安）

この3つだけでも、ユーザーは収入感をすぐ把握できる。

### 2.2 補足導線

初期表示では詳細式を見せすぎない。
代わりに、以下のような折りたたみ説明やツールチップを推奨する。

- 「この手取りはどう計算している？」
- 「どこまで概算？」

展開時に次を説明する。

- 給与所得控除
- 社会保険料
- 所得税
- 住民税
- 控除未反映であること

## 3. 文言の出し分け

### 3.1 推奨ラベル

- `年収（額面）`
- `手取り（概算）`
- `月額手取り（目安）`
- `年間余剰（概算）`

### 3.2 避けたいラベル

- `手取り`
  - 理由: 正確値と誤解されやすい
- `可処分所得`
  - 理由: 一般ユーザーには少し固い

## 4. 注意書きのベストプラクティス

注意文は長くしすぎず、以下の3点を含める。

- 独身・扶養なし・給与所得のみの簡易モデルであること
- 控除や自治体差分は反映していないこと
- 実際の給与明細とは差が出ること

推奨文言例:

```text
手取り額は、独身・扶養なし・給与所得のみを前提にした概算です。
控除や自治体差分は反映していないため、実際の給与明細とは異なる場合があります。
```

## 5. 年次シミュレーションとの接続

家計入力で見せた「手取り（概算）」と、年次シミュレーションの収入計算は同じロジックであることが重要。

そのため、結果画面や年次表では次の関係を短く見せると理解しやすい。

```text
手取り収入 + 追加収入 - 支出 = 年間余剰
```

さらに投資配分を見せるときは、以下の順序で説明する。

```text
年間余剰
→ 投資に回す額
→ 現金として残る額
```

## 6. 内訳を見せるなら

将来的に詳細モーダルを追加する場合は、以下の表示順を推奨する。

1. 額面年収
2. 給与所得控除
3. 社会保険料
4. 課税所得
5. 所得税
6. 住民税
7. 手取り年収
8. 月平均手取り

税金から見せるより、年収から順番に引いていく構造のほうが理解しやすい。

## 7. デザイン上の注意

- 手取りは強調色で見せる
- 注意書きは本文より弱めの色で出す
- 内訳は必要時だけ表示し、初期状態では情報量を増やしすぎない
- 「概算」であることは小さくしすぎず、目に入る位置に置く

## 8. FigmaMake 依頼時の要点

FigmaMakeへ依頼する際は、以下を明示するとズレにくい。

- 手取りは固定率ではなく、給与所得控除・社会保険料・所得税・住民税の順で概算する
- 初期表示では結果サマリー優先、式は詳細表示に回す
- 年次シミュレーションと家計入力で、同じ手取り概算ロジックを使っている前提をUIでも示す
- 「概算」であることを常に明示する
