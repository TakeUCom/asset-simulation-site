## 作成対象

ライフプランシミュレーションWebシステムの主要画面を作成してください。

必須画面:

1. 基本情報入力画面
2. 家計入力画面
3. 教育費設定画面
4. 投資設定画面
5. シミュレーション結果画面
6. シナリオ比較画面

補助画面:

- 新規作成開始モーダル
- シナリオ一覧画面

## プロダクト理解

このシステムは、子どもの人数、年齢差、教育費、家計、投資条件をもとに、将来のライフプランをシミュレーションするWebサービスです。

特に重要なのは以下です。

- 子どもの人数ごとの差分が分かること
- 教育費のピーク時期が分かること
- 投資あり/なしで将来資産がどう変わるかが分かること
- 入力が多くても、段階的に迷わず進めること
- 結果が厳しい場合でも、責めるような印象ではなく、落ち着いて見直せること

## UI/UX の最重要要件

以下を必ず満たしてください。

### 1. Webシステムとして実用的であること

- 見た目だけでなく、実際の運用を想定した情報量に耐えられるレイアウトにしてください
- フォーム、テーブル、比較、グラフ、サマリーが実務的に成立することを重視してください
- 長い入力導線でも、ユーザーが途中で迷いにくい構成にしてください
- 状態変化、選択状態、エラー状態、未入力状態、比較中状態が想像できるデザインにしてください

### 2. 結果画面は「結論 → 理由 → 詳細」の順にすること

- 最上部で、現在のプランが安全か、注意か、見直しが必要か分かるようにしてください
- その次に、なぜその結果なのかを短文で示してください
- その後に、KPI、推移グラフ、比較、詳細表を配置してください

### 3. 入力画面は負荷を軽くすること

- ステップ形式で進行状況を表示してください
- 各画面に途中サマリーを表示してください
- 数字入力には単位、補助文、初期値またはテンプレート的な導線を用意してください
- 初回ユーザーでも入りやすいように、新規作成開始モーダルでテンプレート開始を用意してください

### 4. 比較画面は意思決定支援にすること

- ただ横並びにするだけではなく、どのシナリオが最も現実的か分かるようにしてください
- 比較対象は最大 3 件を前提に、見やすく整理してください
- 重要KPIを優先し、情報過多にしすぎないでください

## デザインの方向性

### 目指す印象

- フレンドリー
- やわらかい
- 親しみやすい
- 家族向けで安心感がある
- 信頼感がある
- 情報が整理されていて分かりやすい

### 避けたい印象

- 銀行や証券サービスのように硬すぎる
- 数字ばかりで圧迫感が強い
- 幼すぎる
- AIっぽい紫中心の汎用デザイン
- 装飾過多で読みにくい

## ビジュアル指示

### カラー

以下をベースにしてください。

- Primary Green: `#2F7D6B`
- Primary Soft: `#E4F3EE`
- Secondary Orange: `#F3B664`
- Secondary Soft: `#FFF4E3`
- Accent Blue: `#5B8DEF`
- Accent Coral: `#E9856E`
- Background: `#F8FBFC`
- Surface: `#FFFFFF`
- Main Text: `#1F2A2E`
- Sub Text: `#4E5B61`
- Border: `#D7E0E4`

ルール:

- 緑をメインCTAとアクティブ状態に使う
- 青は比較や投資関連に使う
- コーラルは教育費ピークや注意喚起に使う
- 背景は白ベースだが、薄い色面で整理感を出す
- KPIカードは白背景ベースで、色はラベルや補助要素に使う

### タイポグラフィ

- 日本語UIとして読みやすいサンセリフ
- 数字は見やすく、KPIはしっかり強調
- 見出しは柔らかいが信頼感を持たせる
- 情報量が多くても読み疲れしないことを優先

### 形状・余白

- 8px グリッドベース
- カードは大きめの角丸
- 影は控えめ
- 余白はやや広め
- セクション単位で情報のまとまりが分かること

## システムとして考慮してほしいこと

Figma Make では、以下も表現してください。

- コンポーネントの再利用性が高いこと
- 同じUIルールで入力画面を横展開できること
- PCとモバイルで破綻しないこと
- 長いフォームでの視線移動が自然であること
- 表やグラフが将来的にデータ量増加に耐えられそうなこと

## 各画面の特に重視してほしいポイント

### 基本情報入力画面

- 最初の入力画面として心理的負荷を下げる
- 子どもの人数に応じた動的入力が自然に見える
- ステップとサマリーで、迷わず次へ進める

### 家計入力画面

- 収入、支出、積立のグルーピングが明快
- 支出項目は最初から出しすぎず、追加できる設計に見せる
- 入力中に月次/年次サマリーが見える

### 教育費設定画面

- 子どもごとの設定構造が分かりやすい
- タブまたはカードで整理されている
- 教育費ピークが視覚的に想像しやすい

### 投資設定画面

- 難しさを感じさせない
- 数値入力だけでなく、プリセットや補助説明がある
- 投資あり/なしの差が直感的に伝わる

### シミュレーション結果画面

- 最重要画面として完成度を高くする
- 総合ステータス、重要インサイト、KPI、グラフ、明細の順に整理する
- ユーザーが一目で「今のままでよいか」を判断できる

### シナリオ比較画面

- 比較対象ごとの差が分かりやすい
- 横比較でも詰まりすぎない
- 最有力案が自然に分かる

## 実行用の最終依頼

上記4資料を前提に、ライフプランシミュレーションWebシステムのUIデザインを作成してください。

単なる見た目のきれいさではなく、Webシステムとして入力しやすく、比較しやすく、結果を理解しやすいことを重視してください。

デザインは、フレンドリーで家族向けの安心感がありつつ、信頼感もある方向で作成してください。
難しい金融サービスに見せず、でもチープにも見せない、生活に近い温度感で設計してください。

入力画面はステップ形式、途中サマリー付き、テンプレート開始ありで設計してください。
結果画面は「結論 → 理由 → 詳細」の順にしてください。
比較画面は、最大3シナリオで意思決定しやすい形にしてください。

コンポーネント再利用性、レスポンシブ性、情報量への耐性も考慮して、実装につながるWebシステムUIとして成立する提案にしてください。
