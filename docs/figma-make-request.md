# Figma Make 依頼指示書

## 1. 依頼の目的

ライフプランシミュレーションサイトのUIデザインを作成してください。
このサービスは、子どもの人数や年齢差、教育費、家計、投資条件をもとに、将来のライフプランをシミュレーションするものです。

特に重要なのは以下です。

- 子どもの人数ごとの差分比較が分かりやすいこと
- 教育費のピーク時期が把握しやすいこと
- 投資あり/なしで将来資産がどう変わるか理解しやすいこと
- 難しそうに見えず、安心して入力・閲覧できること

この依頼では、Figma 上でワイヤーより一歩進んだ、実際のプロダクトUIとして成立する画面デザインを作ってください。

## 2. 作成対象

以下の6画面を優先して作成してください。

1. 基本情報入力画面
2. 家計入力画面
3. 教育費設定画面
4. 投資設定画面
5. シミュレーション結果画面
6. シナリオ比較画面

必要であれば、以下も補助的に作成してください。

- 新規作成開始モーダル
- シナリオ一覧画面

## 3. 参考ドキュメントの前提

以下の内容を踏まえてデザインしてください。

- 画面一覧・画面定義・機能一覧
- デザインシステム指示書

前提として、以下の体験を中心に設計してください。

- 長い入力でも段階的に進められる
- 入力中に現在の前提や概算が分かる
- 結果は「結論 → 理由 → 詳細」の順で理解できる
- 比較は分析のためではなく、意思決定のために使える

## 4. デザインの方向性

### 4.1 トーン

以下の印象を目指してください。

- フレンドリー
- 親しみやすい
- 家族向けで安心感がある
- 信頼感がある
- 整理されていて分かりやすい

### 4.2 避ける方向

以下の印象は避けてください。

- 銀行や証券サービスのように硬すぎるUI
- 数字ばかりで圧迫感が強いUI
- ポップすぎて幼く見えるUI
- AIっぽい無機質な紫系デザイン
- 装飾過多で情報が読みにくいUI

## 5. ビジュアルルール

### 5.1 カラー

以下をベースカラーとして使ってください。

- Primary Green: `#2F7D6B`
- Primary Soft: `#E4F3EE`
- Secondary Orange: `#F3B664`
- Secondary Soft: `#FFF4E3`
- Accent Blue: `#5B8DEF`
- Accent Coral: `#E9856E`
- Background: `#F8FBFC`
- Surface: `#FFFFFF`
- Main Text: `#1F2A2E`
- Sub Text: `#4E5B61`
- Border: `#D7E0E4`

色の使い方ルール:

- メインCTAやアクティブ状態には Green を使用
- 投資関連の比較や補助情報には Blue を使用
- 教育費ピークや注意ポイントには Coral や Warning 系を使用
- 背景は白ベースにしつつ、薄い色面で整理感を出す
- KPIカードは色ベタではなく、白背景ベースで整理する

### 5.2 タイポグラフィ

方向性:

- 読みやすさ重視
- 日本語で自然に読める
- 数字が見やすい
- 見出しはやわらかいが信頼感のある印象

推奨:

- 日本語: Noto Sans JP 系
- 英数字/補助: Manrope 系

サイズ感:

- 見出しは明確に強弱をつける
- 本文は 14px 以上
- 補足でも 12px 未満は使わない
- KPIの数字は大きく強調する

### 5.3 形状と余白

- 全体は 8px グリッドベース
- カードは 16px 以上の角丸
- ボタン・入力欄は 14px 程度の角丸
- 余白は広めに取り、詰め込みすぎない
- 影はごく弱く、ふんわりした印象にする

## 6. UI/UX 要件

### 6.1 共通

- すべての入力画面でステップ進行が分かること
- すべての入力画面で途中サマリーを見られること
- モバイルでも成立する構成にすること
- 入力項目には単位、補助文、プレースホルダーを適切に付けること

### 6.2 基本情報入力画面

表現したいこと:

- 最初のハードルを低く見せる
- 長い設定の入口として、入力負荷を感じさせすぎない

必要な要素:

- ステップ表示
- シナリオ名
- 本人/配偶者年齢
- 子どもの人数
- 年齢差や出産予定時期
- ライフイベントメモ
- テンプレート選択補助
- 現在の入力サマリー

### 6.3 家計入力画面

表現したいこと:

- 複雑な入力を、収入/支出/積立に整理して分かりやすく見せる

必要な要素:

- 収入セクション
- 支出セクション
- 積立セクション
- よくある支出カテゴリ追加
- 月次/年間サマリー
- 入力漏れヒント
- 右サマリー

### 6.4 教育費設定画面

表現したいこと:

- 子どもごとの設定がしやすい
- 将来の教育費ピークが想像しやすい

必要な要素:

- 子どもごとのタブまたはカード
- 進学パターン選択
- 学年別教育費入力
- 塾代入力
- 補填額入力
- 教育費テンプレート
- 教育費推移プレビュー
- 家計への影響の短文表示

### 6.5 投資設定画面

表現したいこと:

- 難しさを感じさせず、安心して条件設定できる
- 投資あり/なし比較の意味が直感的に伝わる

必要な要素:

- 毎月積立額
- 年間追加投資額
- 想定利回り
- 投資開始/終了時期
- 貯蓄のみ比較のON/OFF
- 投資スタイルプリセット
- 簡易プレビュー
- リスク説明

### 6.6 シミュレーション結果画面

最重要です。以下の順序で設計してください。

1. 総合ステータス
2. 重要な気づき
3. KPI
4. 推移グラフ
5. 比較サマリー
6. 詳細テーブル

必要な要素:

- 総合ステータス: 安全 / 注意 / 要見直し
- 最終資産残高
- 年間余剰額
- 教育費ピーク年
- 赤字年
- 最大不足額
- 投資あり/なし比較
- 子ども人数別比較サマリー
- 年次資産推移グラフ
- 教育費推移グラフ
- 投資比較グラフ
- 詳細テーブル
- アラートボックス

重要:

- 結果が悪い場合でも、責めるような見せ方にしない
- 注意喚起はやさしく、でも分かりやすく
- 「何が原因か」が一目で分かること

### 6.7 シナリオ比較画面

表現したいこと:

- どのシナリオが最も現実的か判断しやすい
- 情報が多くても比較軸が明確

必要な要素:

- 比較対象ヘッダー
- KPI比較
- 最有力候補表示
- 教育費前提比較
- 投資条件比較
- 資産推移比較
- 赤字年比較
- 並べ替えや比較対象削除

重要:

- 比較対象は最大 3 件前提で見やすくする
- 情報を並べるだけでなく、意思決定を助けるUIにする

## 7. コンポーネントとして用意してほしいもの

- Primary / Secondary / Tertiary Button
- Text Input
- Select
- Choice Chip
- KPI Card
- Step Indicator
- Status Badge
- Alert Box
- Summary Card
- Scenario Card
- Comparison Table
- Graph Container
- Section Header
- Tab / Accordion

## 8. レイアウト要件

### Desktop

- 入力画面は 2 カラム
  - 左: フォーム本体
  - 右: サマリー

- 結果画面は縦方向に
  - 総合判定
  - KPIカード群
  - グラフ群
  - 詳細情報

### Mobile

- 1 カラムに再構成
- サマリーは下部固定または折りたたみ
- 比較画面は横スクロール前提ではなく、縦積みも検討

## 9. モーション方針

- 穏やかで軽いアニメーションにする
- ステップ遷移はフェード + スライド
- ホバーは軽い浮き上がり
- グラフは控えめに出現

## 10. アクセシビリティ

- 色だけで意味を伝えない
- コントラストを十分確保する
- タップ領域を広く取る
- エラー文は原因と修正方法を明記する

## 11. 出力してほしいもの

以下を Figma 上で整理して作成してください。

- 主要6画面の完成UI
- 使用コンポーネントのルール化
- 配色・文字・余白ルールが分かる簡易デザインシステム
- Desktop と Mobile の両方の考え方が分かるレイアウト

## 12. 最終依頼文

以下をそのまま制作指示として解釈してください。

ライフプランシミュレーションサイトのUIデザインを作成してください。
子どもの人数ごとのライフプラン差分、教育費ピーク、投資有無による将来資産差分を、安心感があり親しみやすいUIで見せることが目的です。

デザインはフレンドリーでやわらかく、家族向けで安心感があり、でも信頼感もあるものにしてください。
金融サービスのように硬すぎず、幼すぎず、生活に近い温度感で設計してください。

ライトテーマをベースに、深みのあるグリーン、やわらかいオレンジ、比較用のブルーを使ってください。
背景は白ベースにしつつ、淡い色面で整理感を出してください。

入力画面はステップ形式で、進行状況と途中サマリーを見せてください。
結果画面は「結論 → 理由 → 詳細」の順で構成し、比較画面は最大3シナリオを比較しやすい設計にしてください。

テンプレート開始、サマリーカード、KPIカード、アラート、比較テーブル、グラフコンテナなどのコンポーネントも含めて、統一感あるUIシステムとして作成してください。
