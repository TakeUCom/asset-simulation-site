# ライフプランシミュレーションサイト 画面一覧・機能一覧・簡易版画面定義書

## 1. ドキュメントの目的

本ドキュメントは、ライフプランシミュレーションサイトの画面設計を進めるための簡易版画面定義書である。
Figma でワイヤーやUI設計を行う前提で、以下を 1 ファイルに集約している。

- 画面一覧
- 機能一覧
- 各画面の目的
- 画面ごとの表示項目
- 入力項目
- アクション
- 出力内容

## 2. プロダクト前提

### 2.1 サービスの目的

子どもの人数や年齢差、教育費、家計、投資条件をもとに、将来のライフプランをシミュレーションする。
特に、子どもの人数ごとの差分比較と、投資有無による将来資産の違いを可視化することを主目的とする。

### 2.2 設計方針

- 入力と結果を分離する
- 子どもの人数別比較を中心体験にする
- 投資シミュレーションを主要機能として扱う
- 詳細明細とサマリーを両立する
- スマホでも使える構成にする
- 初回でも迷わないよう、テンプレートと初期値を用意する
- 長いフォームは、ステップ入力と途中サマリーで負荷を下げる
- 結果画面では、結論、注意点、詳細の順で優先表示する

### 2.3 UI/UX 改善方針

- 新規作成時は「ゼロから入力」だけでなく、テンプレート開始を用意する
- 各入力画面に共通して、進行状況と簡易サマリーを表示する
- 数値入力には、補助テキスト、単位、推奨値、初期値を付ける
- 結果画面は「安心か危険か」を先に伝え、その後に理由を見せる
- 比較画面は、比較対象を 3 件までに絞り、意思決定しやすくする

## SCR-01 トップページ

### 画面の目的

サービスの概要を伝え、シミュレーション開始へ誘導する。

### 想定UIブロック

- ヘッダー
- ヒーローエリア
- サービス説明
- 主な特徴紹介
- CTA エリア
- フッター

### 表示項目

| 項目名 | 内容 |
|---|---|
| サービス名 | ライフプランシミュレーションサイト名 |
| サブコピー | 子どもの人数ごとの将来資産を見える化する訴求文 |
| 説明文 | 家計・教育費・投資をまとめて試算できる説明 |
| 特徴一覧 | 子ども人数比較、教育費推移、投資比較など |
| 開始ボタン | シミュレーション開始導線 |
| シナリオ一覧導線 | 保存済みシナリオへの導線 |

### アクション

- シミュレーションを始める
- 保存済みシナリオを見る

### Figma 用メモ

- 初回ユーザー向けの安心感を重視
- 比較機能と投資シミュレーションを主訴求にする

## SCR-02 シナリオ一覧画面

### 画面の目的

保存済みシナリオの一覧管理、新規作成、複製、比較開始を行う。

### 想定UIブロック

- ヘッダー
- 一覧ツールバー
- シナリオカード一覧
- 比較対象選択エリア

### 表示項目

| 項目名 | 内容 |
|---|---|
| 新規作成ボタン | シナリオ作成開始 |
| 検索・絞り込み | 必要であれば後続で追加 |
| シナリオ名 | 例: 子ども2人_投資あり |
| 作成日/更新日 | 最終更新日時 |
| 前提サマリー | 子ども人数、投資条件、教育費前提など |
| 主要結果 | 最終資産残高、赤字年有無、教育費ピーク年 |
| 複製ボタン | シナリオ複製 |
| 編集ボタン | 条件編集 |
| 比較選択チェック | 比較対象への追加 |
| 比較実行ボタン | 比較画面へ遷移 |

### アクション

- 新規作成
- 編集
- 複製
- 比較対象に追加
- 比較開始

### Figma 用メモ

- 一覧はカード形式でもテーブル形式でも成立
- モバイルではカード型、PCでは表形式も検討可能
- 新規作成ボタン押下時に、直接フォームへ飛ばすのではなく開始モーダルを出す

### 想定UIブロック

- モーダルヘッダー
- 作成方法選択カード

- 開始ボタン

### 表示項目

| 項目名 | 内容 |
|---|---|
| ゼロから作成 | 全項目を手入力で開始 |
| テンプレートから作成 | 例: 子ども1人、子ども2人、投資あり標準型 |

### アクション

- テンプレートを選ぶ

### Figma 用メモ

- 初回の心理的ハードルを下げる役割を持たせる

## SCR-03 基本情報入力画面

### 画面の目的

シミュレーションの基本前提となる世帯情報・家族構成を入力する。

### 想定UIブロック

- 画面タイトル
- 進行ステップ表示
- 入力フォーム
- 右サマリーエリア
- 保存/次へボタン

### 入力項目

| 項目名 | 入力形式 | 必須 | 備考 |
|---|---|---|---|
| シナリオ名 | テキスト | ○ | 後から変更可 |
| 本人年齢 | 数値入力 | ○ | 年齢 |
| 配偶者年齢 | 数値入力 | △ | 単身にも対応するなら任意 |
| 子どもの人数 | セレクト or 数値入力 | ○ | 0〜複数人 |
| 子どもの年齢差 | 数値入力 | △ | 2人以上の時に表示 |
| 第1子の予定時期 | 年/月選択 | △ | 既存の子どもがいない場合に利用 |
| 第2子以降の予定時期 | 年/月選択 | △ | 必要に応じて追加 |
| ライフイベントメモ | テキストエリア | △ | 転職、育休など |
| 初期設定テンプレート | チップ選択 | △ | 例: 子ども2人想定 |

### 表示項目

| 項目名 | 内容 |
|---|---|
| 進行状況 | 全ステップに対する現在位置 |
| 現在の前提サマリー | 世帯年齢、子ども人数などの簡易表示 |
| 完了予測 | 残りステップ数の目安 |

### アクション

- 一時保存
- 次へ
- 戻る

### 入力バリデーション観点

- 年齢は現実的な範囲に制限
- 子どもの人数 0 の場合は教育費入力をスキップ可能にする
- 子ども人数に応じて入力欄を動的に増減させる

### Figma 用メモ

- 子ども人数入力に応じてフォームが動的変化するUIが必要
- ステップフォーム形式が相性よい
- PC では右サイドにサマリー、モバイルでは下部固定サマリーを検討

## SCR-04 家計入力画面

### 画面の目的

日常の収入・支出・積立条件を入力し、基礎となる家計キャッシュフローを定義する。

### 想定UIブロック

- 進行ステップ表示
- 年収/収入セクション
- 支出セクション
- 積立セクション
- 入力サマリー
- 右サマリーエリア

### 入力項目

| 項目名 | 入力形式 | 必須 | 備考 |
|---|---|---|---|
| 本人年収 | 数値入力 | ○ | 年額 |
| 配偶者年収 | 数値入力 | △ | 年額 |
| 本人ボーナス年額 | 数値入力 | △ | 年額 |
| 配偶者ボーナス年額 | 数値入力 | △ | 年額 |
| 毎月の生活費 | 数値入力 | ○ | 食費、日用品など |
| 毎月の住居費 | 数値入力 | △ | 家賃等を含める場合 |
| 毎月の固定費 | 数値入力 | ○ | 通信、保険、サブスクなど |
| 毎月のその他支出 | 数値入力 | △ | 任意 |
| 毎月の貯蓄額 | 数値入力 | △ | 投資を除く現金貯蓄 |
| 毎月の特別積立 | 数値入力 | △ | 教育費積立など |
| 昇給率 | 数値入力 | △ | 年率 |
| 収入変動イベント | テキストエリア | △ | 育休、時短、転職など |
| よくある支出カテゴリを追加 | ボタン | △ | 保険、通信、車などを追加 |

### 表示項目

| 項目名 | 内容 |
|---|---|
| 月次収支サマリー | 入力中の収支差額 |
| 年間収支サマリー | 年間ベースの差額 |
| 入力漏れヒント | 未入力の代表項目を案内 |

### アクション

- 一時保存
- 次へ
- 戻る
- 再計算

### Figma 用メモ

- 「収入」「支出」「積立」を明確に分ける
- 入力中にサイドエリアで簡易サマリー表示すると分かりやすい
- 支出は最初から全項目を出しすぎず、主要項目 + 追加方式が望ましい

| 進学パターン | セレクト | ○ | 公立/私立など |
| 幼少期養育費 | 数値入力 | △ | 月額または年額 |

| 中学生教育費 | 数値入力 | △ | 年額 |

| 大学生教育費 | 数値入力 | △ | 年額 |
| 塾代 | 数値入力 | △ | 学年別でも可 |
| 補填額/支援額 | 数値入力 | △ | 児童手当等を含むなら補正に利用 |

| 項目名 | 内容 |

### アクション

- 子ども追加

- 一時保存
- 次へ
- 戻る

### Figma 用メモ

- 子どもごとに同じ構造を繰り返すUIが必要
- タブ型かカード型のどちらかで整理
- 初期値を読み込んで微調整する流れを前提にした方が使いやすい

投資前提を入力し、貯蓄のみのケースと比較できる条件を定義する。

### 想定UIブロック

- 投資条件入力エリア
- 比較条件エリア
- 結果イメージプレビュー
- リスク説明エリア

### 入力項目

| 項目名 | 入力形式 | 必須 | 備考 |
|---|---|---|---|
| 毎月の投資積立額 | 数値入力 | ○ | 月額 |
| 年間追加投資額 | 数値入力 | △ | ボーナス投資など |
| 想定利回り | 数値入力 | ○ | 年率 |
| 投資開始時期 | 年/月選択 | △ | 今すぐ開始も可 |
| 投資終了時期 | 年/月選択 | △ | 任意 |
| 貯蓄のみケースを比較する | チェックボックス | ○ | ON/OFF |
| リスク前提メモ | テキストエリア | △ | 任意 |
| 投資スタイルプリセット | チップ選択 | △ | 保守、標準、積極 |

| 項目名 | 内容 |
|---|---|

### アクション

- 一時保存
- シミュレーション実行

### Figma 用メモ

## SCR-07 シミュレーション結果画面

### 画面の目的

シミュレーション結果を総合的に表示し、現在条件での将来見通しを把握する。

### 想定UIブロック

- 総合判定エリア
- 結果サマリーカード
- 重要インサイトエリア
- 年次資産推移グラフ
- 子ども人数別比較サマリー
- 教育費推移グラフ
- 投資比較グラフ
- 詳細テーブル
- アラートエリア

### 表示項目

| 項目名 | 内容 |
|---|---|
| 最終資産残高 | シミュレーション終了時点の残高 |
| 総合ステータス | 安全、注意、要見直しの 3 段階など |
| 年間余剰額平均 | 平均的な余剰額 |
| 教育費ピーク年 | 最も教育費負担が高い年 |
| 赤字年 | 資金不足が発生する年 |
| 最大不足額 | 最も厳しい年の不足額 |
| 投資あり残高 | 投資ケースの最終残高 |
| 貯蓄のみ残高 | 非投資ケースの最終残高 |
| 差分 | 投資有無の差 |
| 子ども人数別サマリー | 1人、2人、3人などの比較結果 |
| 重要インサイト | 例: 教育費ピーク時に余剰が小さくなる |

### 詳細表示項目

| 項目名 | 内容 |
|---|---|
| 年齢 | 世帯主年齢等 |
| 年次収入 | 年ごとの収入 |
| 年次支出 | 年ごとの支出 |
| 教育費 | 年ごとの教育費 |
| 年次余剰/不足 | 年ごとの差額 |
| 累積貯蓄 | 貯蓄ケースの累積 |
| 累積運用 | 投資ケースの累積 |

### アクション

- 条件を編集する
- シナリオを保存する
- 複製する
- 比較に追加する
- 共有用に要点を見る

### Figma 用メモ

- 最初に重要指標、その下にグラフ、その下に詳細テーブルの順が分かりやすい
- PC では情報量多め、モバイルでは重要指標優先
- 「結論 → 理由 → 詳細」の順で情報設計する

## SCR-08 シナリオ比較画面

### 画面の目的

複数シナリオの差を横断的に見て、どの条件が最も現実的か判断する。

### 想定UIブロック

- 比較対象ヘッダー
- KPI 比較テーブル
- 比較グラフ
- コメント/気づきエリア
- 比較結果ハイライトエリア

### 表示項目

| 項目名 | 内容 |
|---|---|
| 比較対象シナリオ名 | 複数表示 |
| 子どもの人数 | シナリオ別の人数 |
| 教育費前提 | 公立/私立等 |
| 投資条件 | 積立額、利回りなど |
| 最終資産残高 | シナリオ別に比較 |
| 赤字年有無 | シナリオ別に比較 |
| 最大不足額 | シナリオ別に比較 |
| 教育費ピーク年 | シナリオ別に比較 |
| 投資差分 | 投資有無の差額 |
| 推奨候補表示 | 条件に応じた最有力候補 |

### アクション

- 比較対象を外す
- シナリオ詳細へ戻る
- 新しい比較を始める
- 比較対象を並べ替える

### Figma 用メモ

- 列比較の情報設計が中心
- 比較軸が多くなりすぎないよう、重要KPIを優先表示する
- 比較対象は最大 3 件程度までに絞る前提が見やすい

## 7. Figma 作成時の補足指示

### 7.1 必ず必要なコンポーネント候補

- ヘッダー
- ステップインジケーター
- KPIカード
- 入力フォーム
- セレクトボックス
- タブ or アコーディオン
- 比較テーブル
- グラフ表示領域
- アラートボックス
- CTA ボタン
- サイドサマリー
- テンプレート選択カード
- ステータスバッジ
- インサイトメッセージ

### 7.2 デザイン上の優先ポイント

- 難しい金融サービスに見せすぎない
- 家族向けサービスとして安心感のある情報設計にする
- 入力項目が多いため、段階入力で負荷を下げる
- 結果画面は「今どうか」「将来どうなるか」「何が原因か」が一目で分かる構成にする
- 初回はテンプレート利用、慣れたら詳細編集、という二段階UXを前提にする
- 比較画面は分析ツールというより、意思決定支援画面として設計する
